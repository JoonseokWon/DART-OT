# DART-OT 요구사항

- UI·UX 적용 여부: 적용 / 화면 있음
- 목적: 회사별 DART 정기보고서의 차입금과 이자비용을 검토하는 Windows 데스크톱 도구의 수집 신뢰성과 원문 추적성을 개선한다.
- 사용자: 공시 원문과 계산 결과를 대조하는 회계·감사 실무자.
- 작업 위치: 기존 DART-OT 저장소. 다른 프로젝트와 상위 폴더를 변경하지 않는다.

## 이번 버전 v0.1.1

1. DART 오류를 자료 없음과 구분한다. 인증키·요청 한도 오류를 사용자에게 해결 방법과 함께 표시한다.
2. 일시적인 HTTP/연결 장애는 제한된 횟수로 재시도하고 동시 요청 간격을 조절한다.
3. 오류 응답을 원문 또는 빈 재무제표로 캐시하지 않는다.
4. 기존 Excel 시트 구성을 유지하고 접수번호·원문파일·줄번호·추출 문맥을 담은 `원문추적` 시트를 추가한다.
5. 결과가 없는 조회와 작업 스레드 오류에서도 입력 화면으로 돌아가 다시 실행할 수 있다.
6. 회귀 테스트, Windows 릴리스 검증, 설계·진행·인계 기록을 남긴다.

## 사용 흐름과 예시

- 입력: API 키, 회사명 또는 종목코드, 조회 시작·종료 연도, 중요성 프리셋.
- 흐름: 회사 검색 → 회사 선택 → 검토 실행 → 진행률 → 결과 표 → 결과 파일 열기.
- 출력: 기존 결과 시트 + 원문추적. 예: 삼성전자 / 분기보고서 (2026.03) / 접수번호 / XML 파일명 / 줄번호 / 추출에 사용한 문맥.
- 예외: 잘못된 키는 키 확인 안내, 한도 초과는 이용 한도 안내, 연결 장애는 재시도 후 인터넷 확인 안내. 조회 결과 0건은 파일을 만들지 않고 기간 변경 안내.

## 완료 기준

- 인증 오류·XML 오류 응답·일시 장애·정상 자료 없음 시나리오를 자동 테스트한다.
- 동일 접수번호를 오류 후 재조회할 수 있고 실패 응답을 캐시하지 않는다.
- 원문추적 셀에서 접수번호·파일명·줄번호·추출 문맥을 복구할 수 있다.
- GUI에서 오류 후 복귀와 다시 실행, 결과 파일 열기 안내를 확인한다.
- 이번 변경만 커밋하고 GitHub 릴리스에 Windows ZIP과 SHA256이 게시되는지 확인한다.

## 제외 범위·가정

- 이자율 판정 기준과 과거 산출 파일을 변경하지 않는다. 원문 추적성 개선을 정확도 상승 수치로 표현하지 않는다.
- 독립적인 정답 데이터 대조, 과거 12개 기업의 전체 재수집, 모바일 앱 신규 개발은 이후 작업이다.
- 최신 수정공시 선택 정책과 기존 청록색 브랜드를 유지한다.
- GitHub 릴리스 빌드는 기존 Windows Actions를 사용한다. 실제 API 재조회는 저장된 키를 노출하지 않는 범위에서 최소한으로 확인한다.

# DART-OT 화면 설계

UI·UX 적용 여부: 적용 / 화면 있음

## 화면과 흐름

- 입력 화면: API 키·회사·기간·기준을 입력하고 회사 검색과 검토 실행을 순서대로 수행한다.
- 진행·결과 화면: 진행률, 핵심 건수 카드, 보고서별 비교 표, `입력으로 돌아가기`, `결과 파일 열기` 순서로 읽는다.
- 데이터 비교는 기존 표를 사용한다. 요약 수치는 기존 카드 구성을 유지하며 별도 장식용 벤토 그리드는 추가하지 않는다.
- 오류가 나면 구체적인 문제와 다음 행동을 표시하고 입력 내용을 유지한다. 파일이 만들어지지 않았으면 열기 버튼은 비활성 상태로 유지한다.
- 성공 후 `원문추적` 시트에서 접수번호·파일·줄번호로 검토 근거를 찾도록 짧게 안내한다.
- 하단 파일 버튼 공간을 표보다 먼저 확보한다. 표의 가로·세로 스크롤로 작은 창에서도 모든 열과 행에 접근한다.
- 결과 화면에서는 API 키 입력 패널을 접고 상단에 작은 DART-OT 브랜드를 표시한다. 조건 화면으로 복귀하면 입력 패널과 기존 브랜드 헤더를 복원한다. 최소 창에서도 비교 표의 제목과 데이터 행이 보이도록 공간을 확보한다.

## 공통 시각 규칙

- 기존 브랜드 유지: 강조색 #16A58F, 배경 #F2F7F6, 본문 #15312E, 보조 #647976.
- 제목 → 진행 상태 → 요약 → 결과 표 순서의 위계와 기존 여백을 유지한다.
- 긴 오류와 안내는 줄바꿈한다. 상태는 색상과 문구를 함께 사용한다.
- 버튼은 행동을 나타내고 기본 키보드 탭 이동과 포커스 표시를 유지한다.
- Windows 데스크톱이 이번 검증 대상이며 웹·모바일 레이아웃 변경은 포함하지 않는다.

## 검증 방법

- 실제 Windows 화면에서 입력·검색·진행·성공·오류·복귀 상태를 확인한다.
- 기본 창과 작은 창에서 주요 버튼, 긴 한국어 안내, 표 스크롤, 키보드 이동을 확인한다.
- 네트워크 오류는 모의 응답으로 재현하여 버튼이 다시 활성화되는지 자동 검증한다.
- 오류를 전달하는 Tk after 콜백은 예외 변수가 소멸한 후에도 메시지를 표시해야 한다.
